🖊 【AI新玩法，新概念】

Flask 之父 Armin Ronacher 炮轰："Better Models, Worse Tools"

动态：Flask 框架作者 Armin Ronacher 7月4日发文揭示一个诡异现象——Opus 4.8 和 Sonnet 5 等新模型在调用编辑工具时，反而会在输出中凭空发明额外的 JSON 字段，导致工具调用失败。他称之为"模型越强，工具调用越差"的系统性问题。

解读：这暴露了一个深层问题：模型在自然语言上的"聪明"不直接等价于工具调用的"精准"。因为工具调用依赖严格的 JSON Schema 合规，而新模型在增强推理能力时引入了更多"自由度"——自由度过高，反而违反了协议约束。Ronacher 的结论是：工具侧必须建立更强大的防御层，不能指望模型"自学成才"。

落地场景：如果你在开发基于 Claude/OpenAI 的工具链，务必在 Agent 的输出层加入严格的 Schema 校验和重试机制，而不是默认"新模型肯定更好"。

Claude Fable 5 "内心独白" 泄露："TOO_DUMB_TO_NEED_FABLE"

动态：Claude Fable 5 回归当天被开发者抓包：大量轻量级问题被自动回退到 Opus 4.8 处理，日志中出现 "TOO_DUMB_TO_NEED_FABLE" 标签。还有用户晒出 Fable 5 在 Codeforces 解题时的"内心独白"——原本精修的思考链变成了碎碎念的感叹词堆砌。

解读：这不是 bug，是 Anthropic 在降本压力下的"隐性降级"策略：前端告诉你是 Fable 5，后端实际调用的是 Opus 4.8。对开发者意味着：不能只看模型名称，需要主动监控 API 返回的实际模型标识和 Token 消耗模式，防止被"偷梁换柱"。
